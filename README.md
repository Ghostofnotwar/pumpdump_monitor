# Pump & Dump Monitor

Telegram-бот для наблюдения за резкими движениями USDT-перпетуалов Bybit. Сбор рынка, доставка уведомлений и HTTPS Mini App работают в одном процессе. Интерфейс и команды — на русском.

**Это информационный монитор, а не торговый робот.** Он не открывает сделки, не хранит биржевые ключи и не гарантирует полноту или скорость сигналов.

## Что реализовано

- PUMP и DUMP относительно цены около начала скользящего окна, по умолчанию 5 минут.
- Персональные направление, порог, минимальный оборот за 24 часа и пауза.
- Таймфрейм свечей отдельно от окна детектора.
- Ограниченный список наиболее ликвидных USDT-перпетуалов; по умолчанию до 500 пар.
- Прогрев истории и подавление сигналов при пропусках данных.
- Антиспам на пару `(чат, инструмент, направление)`, сохраняющийся в SQLite.
- Ограниченная очередь доставки, повтор при временных ошибках, текстовый алерт при недоступности графика.
- PNG-графики Bybit OHLCV, объём и SMA 9. Дополнительные CVD proxy и профиль объёма явно помечены как оценки.
- Mini App: состояние системы, настройки личного чата, последние алерты и графики.
- Проверка HMAC-подписи Telegram `initData`; доступ к API только к данным вошедшего пользователя.
- `/healthz` для liveness, `/readyz` для диагностики готовности, корректное завершение по SIGTERM/SIGINT.
- SQLite WAL, аддитивные миграции, резервное копирование через SQLite backup API.
- Очистка старых графиков и ограничение занимаемого места.

**Не реализованы:** реальные OI, ликвидации, order-flow/CVD по сделкам, FVG/OB/Score, автоматическая торговля. Старые колонки настроек сохранены для совместимости, но не включают эти функции. CVD proxy вычисляется по положению закрытия внутри свечи; профиль объёма предполагает равномерное распределение объёма внутри диапазона свечи.

## Локальный запуск

Нужен Python **3.11** — версия Docker и CI.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
# Заполните BOT_TOKEN в .env. Не добавляйте этот файл в Git.
python main.py
```

Откройте своего бота и отправьте `/start`. HTTP доступен на `http://127.0.0.1:8000`; вне Telegram страница покажет инструкции, но не личные данные. Для Mini App нужен публичный HTTPS URL, например после деплоя на Fly.

Команды: `/start`, `/settings`, `/alerts`, `/pause`, `/resume`, `/test`, `/help`.

- `/test` строит график BTCUSDT, не симулирует процент движения и не добавляет запись в историю сигналов. Повтор — не чаще раза в минуту.
- В группах изменять настройки могут администраторы. Mini App управляет только **личным** чатом пользователя, не группой.
- По умолчанию регистрация открыта любому пользователю Telegram. Для частного бота задайте `ALLOWED_CHAT_IDS`.

## Docker

```bash
cp .env.example .env
# Заполните BOT_TOKEN; при необходимости ALLOWED_CHAT_IDS.
docker compose up --build -d
docker compose logs -f bot
```

SQLite и PNG находятся в именованном volume `/data`. Контейнер запускает приложение от непривилегированного пользователя; entrypoint только подготавливает права volume. HTTP проброшен на loopback хоста.

**Не запускайте два экземпляра с одним BOT_TOKEN:** long polling конфликтует. Не размещайте локальную SQLite на сетевой файловой системе и не масштабируйте этот вариант на несколько машин.

## Как считается движение

1. Раз в `POLL_INTERVAL_SEC` читается общий список тикеров.
2. Для каждой пары хранится ограниченная история временных меток и цен.
3. Базовая цена — ближайший тик **не позже** границы окна, с допуском `max(10 секунд, 3 интервала опроса)`.
4. Пока окно не прогрето или между точками есть слишком большой разрыв, сигнал не создаётся.
5. `change = (last_price / baseline_price - 1) * 100` сравнивается с персональным порогом.
6. Проверяются направление, пауза и оборот за 24 часа. Затем резервируется антиспам и задание попадает в ограниченную очередь.

`timeframe` влияет **только на график**. Изменение окна задаётся `ALERT_WINDOW_SEC`. Вселенная ограничена сверху `MAX_SYMBOLS`; персональный фильтр не добавляет пары за пределами этого списка.

После рестарта история цен прогревается заново. Антиспам и настройки сохраняются. Доставка — best effort, не exactly-once: сбой между принятием сообщения Telegram и фиксацией результата может потребовать повторной проверки; резервирование до отправки также может подавить сигнал при аварийном завершении. Очередь и история не являются брокерской лентой с гарантированной доставкой.

## Конфигурация

Полный шаблон — [`.env.example`](.env.example). Секреты задаются окружением, не исходным кодом.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | обязательно | Токен BotFather |
| `DATABASE_URL` | `sqlite:///data/bot.db` | Только файловый SQLite; другие СУБД не реализованы |
| `SNAPSHOT_DIR` | рядом с БД, `snapshots/` | Каталог управляемых PNG |
| `WEB_APP_URL` | пусто | Публичный HTTPS URL Mini App; без query/fragment |
| `ALLOWED_CHAT_IDS` | пусто | Разрешённые чаты через запятую; пусто — открытая регистрация |
| `PORT` | `8000` | HTTP-порт, сервер слушает `0.0.0.0` |
| `BYBIT_REST` | `https://api.bybit.com` | REST endpoint или доверенный proxy |
| `CLOUDFLARE_PROXY` | пусто | Legacy-алиас, только если `BYBIT_REST` не задан |
| `BYBIT_TIMEOUT_SEC` | `15` | Таймаут одной HTTP-попытки |
| `MAX_CONCURRENT_REQUESTS` | `8` | Параллельные запросы к Bybit |
| `PAIRS_UPDATE_MIN` | `5` | Обновление вселенной, минуты |
| `POLL_INTERVAL_SEC` | `2` | Интервал тиков, 1–60 секунд |
| `ALERT_WINDOW_SEC` | `300` | Окно изменения, 60–3600 секунд |
| `ALERT_COOLDOWN_SEC` | `600` | Антиспам, 60–86400 секунд |
| `MAX_SYMBOLS` | `500` | Максимум инструментов, 1–2000 |
| `MIN_UNIVERSE_VOLUME_USD` | `50000` | Нижний фильтр оборота для общего списка |
| `ALERT_WORKERS` | `2` | Worker'ы доставки, 1–8 |
| `ALERT_QUEUE_SIZE` | `100` | Максимум заданий в очереди |
| `ALERT_RETENTION_DAYS` | `30` | Хранение записей алертов |
| `SNAPSHOT_RETENTION_DAYS` | `7` | Хранение PNG |
| `SNAPSHOT_MAX_MB` | `512` | Мягкий лимит PNG; очистка каждый час |
| `DROP_PENDING_UPDATES` | `false` | Не отбрасывать команды, полученные во время простоя |
| `LOG_LEVEL` | `INFO` | Уровень логирования |

Все времена в интерфейсе и БД — UTC. Прежняя переменная `TZ` больше не управляет расчётами. `SNAP_INTERVAL_SEC` и `MAX_CONCURRENT_SNAPS` удалены: периодических скриншотов нет, графики строятся по событию и сериализуются для потокобезопасности Matplotlib.

## Проверки и резервная копия

```bash
python -m pip install -r requirements-dev.txt
ruff check .
ruff format --check .
python -m pytest -q --timeout=30 --timeout-method=thread
python -m pip check
docker build -t pumpdump-monitor .
```

Тесты используют локальные HTTP-серверы и синтетические свечи; реальный токен и доступ к Bybit не нужны. CI дополнительно собирает Docker-образ.

```bash
python backup_db.py
# Или явно:
python backup_db.py --database data/bot.db --output /secure/path/bot-backup.db
```

Скрипт делает согласованную копию работающей SQLite и проверяет целостность. Не копируйте только `.db` у работающего процесса: часть данных может быть в WAL. Хранилище резервных копий и выгрузку с сервера организуйте отдельно; каталог `backups/` автоматически не очищается.

## Структура

- `main.py` — общий event loop, запуск и остановка всех подсистем.
- `monitor.py`, `detector.py` — сбор, окно движения, очередь и доставка.
- `bybit_client.py` — публичный REST, таймауты, retry, пагинация.
- `db.py`, `settings_rules.py` — SQLite, миграции, проверка настроек и антиспам.
- `chart_builder.py`, `snapshots.py` — графики и хранение PNG.
- `bot_handlers.py`, `auth.py` — команды и проверка подписи Mini App.
- `web_app.py`, `templates/`, `static/` — HTTP API и интерфейс.
- `AUDIT.md` — независимая оценка исходной версии и оставшиеся ограничения.

`railway.json` оставлен для существующего legacy-деплоя; он не настраивает постоянный диск. Для дальнейшей эксплуатации рекомендуется Fly по инструкции выше.
