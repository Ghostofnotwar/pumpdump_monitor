# Независимая техническая оценка

Дата: **2026-10-29**. Исходная точка: `43b7a5f6fbfc40a7250eb4d59e50766431e7308b`.

## Резюме

Исходный репозиторий был прототипом с полезной идеей, но не готовым к круглосуточной эксплуатации сервисом. Основные риски: неверная семантика сигналов, неработающий HTTP/Mini App, отсутствие управляемого жизненного цикла, недостоверные подписи графиков и непостоянное хранение. Исправления сосредоточены на корректности и эксплуатации, а не на добавлении торговых советов или имитации отсутствующих данных.

## Проверка исправленной версии

Локально проверяются:

- выбор базовой цены, отрицательное движение, warm-up, пропуски, NaN/inf, неупорядоченные тики;
- миграция старой SQLite, сохранность настроек, изоляция чатов, атомарный cooldown и его сохранение после перезапуска;
- валидация Telegram-подписи, просрочка, подмена, allowlist, IDOR по истории/изображениям, строгая схема настроек;
- HTTP retry/pagination/timeout на локальном сервере;
- фактическая генерация PNG в обеих темах, дополнительные панели, параллельные вызовы, закрытие figure, очистка при ошибке;
- персональные фильтры, PUMP/DUMP, пауза, очередь, fallback, Forbidden/RetryAfter, закрытие файлов;
- SIGTERM, ошибка старта, fatal worker, остановка всех подсистем;
- согласованность backup и базовые инварианты Fly/Docker-конфигурации.

Точный результат последнего прогона и состав проверок фиксируются в описании PR. Синтетические графики не являются проверкой качества реального рынка.

## Что осталось за пределами этой итерации

1. **Нет подтверждённого production-деплоя.** Нужны аккаунт Fly, billing, секреты и выбранный регион. Доступность Bybit из региона нужно проверить отдельно; смена proxy не должна использоваться для обхода ограничений сервиса.
2. **Нет exactly-once доставки.** Telegram и локальная SQLite не участвуют в общей транзакции. Для строгой очереди нужен transactional outbox/очередь и политика повторов; текущий вариант — ограниченный best-effort монитор.
3. **Один процесс — точка отказа.** Это осознанный компромисс для long polling + SQLite. Fly перезапускает процесс, но не обеспечивает отсутствие простоя. Горизонтальное масштабирование требует другого хранилища и координации.
4. **Ценовые тики, не лента сделок.** REST не гарантирует обнаружение каждого внутриинтервального пампа. Для этого нужен WebSocket, мониторинг разрывов и отдельная оценка лимитов.
5. **Нет реальных OI/ликвидаций/FVG/OB/Score.** Их нельзя достоверно восстановить из одних свечей. Нужен отдельный источник и проверка его лицензии/качества.
6. **Retention — не бесконечный архив.** Записи по умолчанию 30 дней, PNG 7 дней и до мягкого лимита 512 MiB. Резервные копии нужно выгружать и обслуживать отдельно.
7. **Нет backtest/метрик точности.** Порог 5% — пользовательское правило, не доказанное торговое преимущество. Нет оценки precision/recall, комиссий, проскальзывания или исполнимости.
8. **Публичная регистрация по умолчанию сохранена.** Для частного использования задайте `ALLOWED_CHAT_IDS`; публичный сервис потребует квот пользователей и отдельного антиспама HTTP API.

## Рекомендованный порядок дальнейшего развития

Сначала подтвердить стабильный одиночный деплой и резервное копирование, затем собрать реальные метрики задержек/пропусков/доставки. После этого рассмотреть WebSocket и transactional outbox. Новые индикаторы добавлять только с проверяемым источником и честной маркировкой, не возвращаясь к синтетическим OI/ликвидациям.
